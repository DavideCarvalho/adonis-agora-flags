Exposures and tracked events are buffered in the process, written to a **transport** (a log), and a **relay** delivers them to every **sink** at its own pace. The defaults need nothing but your database:

```ts title="config/flags.ts"
import { defineConfig, sinks, transports, analytics } from '@adonis-agora/flags'

export default defineConfig({
  flags: { /* … */ },
  transport: transports.db(),             // the default with Lucid
  sinks: { warehouse: sinks.lucid() },    // the default with Lucid
  analytics: analytics.lucid(),           // the default when the lucid sink exists
})
```

## Transports

| Transport | Notes |
|---|---|
| `transports.db()` | A table in your database. The only one that writes inside your transaction (`track(…, { client: trx })`). Default |
| `transports.redis({ connection })` | Redis Streams, one consumer group per sink. Needs `@adonisjs/redis` |
| `transports.memory()` | Tests and development |

Delivery is at-least-once; every sink ignores duplicates. Events older than `retentionDays` (default 30) are pruned once every sink has them. On Postgres, `partitionEvents: true` partitions the log by month so pruning drops partitions — decide before the first boot.

## Sinks

```ts
sinks: {
  warehouse: sinks.lucid(),
  archive: sinks.parquet({ path: 'storage/flags' }),
  clickhouse: sinks.clickhouse({ url: env.get('CLICKHOUSE_URL'), username: 'flags', password: env.get('CLICKHOUSE_PASSWORD') }),
  posthog: sinks.posthog({ apiKey: env.get('POSTHOG_KEY') }),
  webhook: sinks.callback(async (events) => { /* … */ }),
}
```

Adding a sink later delivers the retained log to it from the beginning. `node ace flags:replay <sink>` sends it again.

## Choosing an analytics backend

| Level | Backend | When |
|---|---|---|
| 1 | `analytics.lucid()` | Up to tens of millions of events a month |
| 2 | `analytics.duckdb({ path })` + `sinks.parquet({ path })` | Long retention, no server. Parquet on disk or S3 |
| 3 | `analytics.clickhouse({ … })` + `sinks.clickhouse({ … })` | High volume, fast queries |

All three return the same numbers for the same data: the database only aggregates, the statistics are computed in one place.

<Callout type="warn">
  `@duckdb/node-api` is an optional dependency with a native binary. Run the relay for the Parquet sink in a worker (see [Deployment](/docs/deployment)), not in web processes.
</Callout>

## Erasure

```sh
node ace flags:forget <subject-id>
```

```ts
await flags.forget(user)
```

Deletes the subject's events and exposures from the log and from every sink that supports it (lucid, ClickHouse, local Parquet files). PostHog erasure goes through PostHog itself.

## Observability

With [`@adonis-agora/diagnostics`](/docs/diagnostics) installed, flags publish four events on `agora:flags:<event>`:

| Event | When | Payload |
|---|---|---|
| `evaluation` | A flag is read | `flag`, `variant`, `reason`, `errorCode`, `subject` |
| `exposure` | An experiment flag is read | The exposure event |
| `track` | `track()` records a conversion | The track event |
| `change` | The console, a command, an approval or a schedule changes the ruleset | `environment`, `version`, `entity`, `key`, `deleted`, `actor`, `changeRequestId` |

The diagnostics OpenTelemetry bridge adds them to the active span, and you can listen to them:

```ts
import { onDiagnostic } from '@adonis-agora/diagnostics'

onDiagnostic('flags', 'change', (event) => {
  logger.info({ ...event.payload }, 'flag changed')
})
```

`change` fires in the process that made the change. Other processes pick the new ruleset up without publishing it again.

For OpenTelemetry's feature-flag attributes (`feature_flag.key`, `feature_flag.result.variant`…) and Sentry flag context, add enrichers:

```ts
import * as Sentry from '@sentry/node'
import { enrichers } from '@adonis-agora/flags'

enrichers: [enrichers.otel(), enrichers.sentry(Sentry)]
```

`enrichers.otel()` records evaluations as `feature_flag.evaluation` span events and takes them over from the diagnostics bridge, so each evaluation appears on the span once. It needs `@opentelemetry/api`, and works without diagnostics.
