The provider takes flags from one of two places:

| | `values` | `source={remoteFlags(...)}` |
|---|---|---|
| Who evaluates | Your Adonis backend, per request | The flags server ([central server](/docs/central-server)) |
| For | Inertia apps | SPAs, mobile, static sites — no Adonis backend of their own |
| Experiments | Read the variant in the controller | Rendering the flag records the exposure |

```sh
npm i @adonis-agora/flags-react
```

## Share the values

Only flags declared with `client: true` are sent — the browser receives values, never targeting rules.

Share them from the Inertia middleware:

```ts title="app/middleware/inertia_middleware.ts"
async share(ctx: HttpContext) {
  return {
    // `await`: all() is async. The `?.` covers pages rendered outside a route (a 404), where the
    // router middleware that sets ctx.flags never ran.
    flags: (await ctx.flags?.all()) ?? {},
  }
}
```

Then wrap the app in `InertiaFlagsProvider`. It starts from the first page and follows the `flags` prop on every Inertia response — visits and reloads:

```tsx title="inertia/app.tsx"
import { InertiaFlagsProvider } from '@adonis-agora/flags-react/inertia'

setup({ el, App, props }) {
  createRoot(el).render(
    <InertiaFlagsProvider initialPage={props.initialPage}>
      <App {...props} />
    </InertiaFlagsProvider>,
  )
}
```

A plain `<FlagsProvider values={props.initialPage.props.flags}>` there would keep the first page's values: `setup` runs once.

## Read them

```tsx
import { Flag, useFlag, useFlagEnabled } from '@adonis-agora/flags-react'

function Player() {
  const newPlayer = useFlagEnabled('new_player')
  const maxUploads = useFlag('max_uploads', 10)
  return newPlayer ? <NewPlayer max={maxUploads} /> : <ClassicPlayer />
}

<Flag name="checkout" is="one_page" fallback={<ClassicCheckout />}>
  <OnePageCheckout />
</Flag>
```

Values are typed from your `config/flags.ts`. Keys are checked too once you turn on `strictKeys` (see [`flags:types`](/docs/declaring-flags)); without it any string is accepted, so flags created in the console work before you regenerate types.

## Live updates

With `realtime: true` in `config/flags.ts` and `@adonisjs/transmit` installed, the server broadcasts every ruleset change. Reload the flags prop when it happens:

```tsx
import { transmit } from '~/transmit'
import { router } from '@inertiajs/react'
import { useFlagsRealtime } from '@adonis-agora/flags-react'

useFlagsRealtime({ transmit, onChange: () => router.reload({ only: ['flags'] }) })
```

## Without Inertia: `remoteFlags`

For an SPA, a static site or anything that does not render through Inertia, the frontend asks the flags API itself. Turn on `browser` in `config/flags.ts`:

```ts title="config/flags.ts"
export default defineConfig({
  flags: { /* … */ },
  browser: {},
})
```

The flags API authenticates with the token, never with cookies, so `@adonisjs/shield`'s CSRF check must skip it, or it refuses the browser's POSTs:

```ts title="config/shield.ts"
import { flagsCsrfExceptions } from '@adonis-agora/flags'

csrf: {
  enabled: true,
  exceptRoutes: (ctx) => flagsCsrfExceptions(ctx.request.url()),
},
```

```tsx
import { FlagsProvider, remoteFlags } from '@adonis-agora/flags-react'

const flags = remoteFlags({ endpoint: '/_flags/token' })

<FlagsProvider source={flags}>
  <App />
</FlagsProvider>
```

`browser` mounts `GET /_flags/token` on your app. It signs the **same user `ctx.flags` uses** into a five-minute token and says where the flags API is:

- **with `@adonisjs/auth`** (sessions, access tokens, any guard): `ctx.auth.user`. Nothing to configure;
- **with `@adonis-agora/authkit-client`**: the authkit identity of the session (`sub`, email, roles, organization), also with nothing to configure;
- with your own `subject` resolver in `config/flags.ts`: whatever it returns;
- nobody signed in: an anonymous token, which gets static values only.

The `attributes` resolver of `config/flags.ts` runs too, so plan, country and the like travel signed inside the token. With `@adonisjs/auth`, that is where the user's targeting data comes from:

```ts title="config/flags.ts"
export default defineConfig({
  flags: { /* … */ },
  browser: {},
  attributes: async (subject) => {
    const user = await User.find(subject.id)
    return { plan: user?.plan, country: user?.country }
  },
})
``` The browser holds the token in memory only (never `localStorage`), fetches a new one shortly before it expires, and retries once with a fresh one if the flags API refuses it.

1. The browser calls `/_flags/token` with its session cookie and gets `{ token, expiresAt, url }`.
2. It calls the flags API at `url` with the token.

Where the flags API is depends on the [topology](/docs/central-server): on a standalone app it is the app itself; on a tenant, the token points the browser straight at the control-plane. The frontend code is the same either way.

- Values arrive on mount, refresh every 30 seconds (an unchanged ruleset costs a `304`), and change instantly through a server-sent event stream.
- Until the first answer, hooks return their fallbacks; `useFlagsStatus()` tells you when values are ready.
- Rendering an experiment flag (`useFlag`, `useFlagEnabled`, `<Flag>`) records the exposure once per page load. The server re-evaluates the flag, so the browser cannot report a variant it was not assigned.
- `useTrack()` records conversions:

```tsx
const track = useTrack()
<button onClick={() => track('signup_click')}>Sign up</button>
```

After sign-in or sign-out, call `flags.reload()`: it drops the token and evaluates for the new user.

### Options

| Option | |
|---|---|
| `endpoint` | The token endpoint. |
| `credentials` | `'include'` when the frontend is on another origin than the app (also allow it in `config/cors.ts`). Default `'same-origin'`. |
| `initial` | A token already in the page, to skip the first request: `browserToken(ctx)` from `@adonis-agora/flags`. |
| `attributes` | Conveniences (locale, screen). Merged under the token's identity: they cannot change who the user is, and rules on them must never gate access. |
| `pollMs`, `stream` | Refresh interval (default 30 s) and the live stream (default on). |

### Apps that hold their own token

A mobile app or SPA that signs in to authkit itself (PKCE) has an access token and no Adonis session. Give it the flags API URL and the token:

```tsx
remoteFlags({ url: 'https://flags.example.com/_flags', token: () => auth.accessToken })
```

and let the flags server accept authkit tokens with [`browser.verifyUser`](/docs/central-server#apps-with-their-own-authkit-token).
