`node ace configure @adonis-agora/flags` registers the console and publishes `config/flags_dashboard.ts`. It is served at `/flags`.

Who may open it and who is acting come from the [identity provider](/docs/authentication) in `config/flags.ts`. You can also set them here, which wins:

```ts title="config/flags_dashboard.ts"
import { defineConfig } from '@adonis-agora/flags/dashboard'

export default defineConfig({
  path: '/flags',
  authorize: async (ctx) => {
    if (!(await ctx.auth.check())) return { redirectTo: '/login' }
    return ctx.bouncer.allows(manageFlags)
  },
  // Who made a change, for the audit log and approvals.
  actor: (ctx) => (ctx.auth.user ? { id: String(ctx.auth.user.id), name: ctx.auth.user.email } : undefined),
})
```

With authkit, `identity: identities.authkit()` in `config/flags.ts` covers both.

<Callout type="warn">
  Without `authorize`, the console is open outside production and answers 403 in production. With approvals on, set `actor` (or sign people in): two anonymous people are the same actor, and nobody can approve their own change.
</Callout>

## What it has

- **Flags.** Create flags with **New flag** (type, default, variants, owner, expiry, browser exposure). Search by tag, owner or staleness. Each flag shows its declared type, default and owner, and what it serves. The kill switch is one click from the list. In the editor: variants, the fallthrough (fixed or split), ordered rules, overrides, prerequisites and experiment settings (layer, holdout, metrics, guardrails, control, confidence). A context tester shows what any subject would get and why. Below that, the flag's history and its scheduled changes, including gradual rollouts.
- **Segments, layers and the global holdout.**
- **Metrics.** Create, edit and delete the metrics experiments use, and see which experiments use each one. Metrics from `config/flags.ts` are listed read-only.
- **Experiments.** Exposures, the sample-ratio check, and per metric the lift, interval, p-value, sequential p-value and verdict. Guardrail alerts, and a button to recompute now.
- **Approvals.** Approve, reject or cancel pending change requests.
- **Environments.** Switch environments, export and import JSON, promote from one environment to another.
- **Hygiene.** The stale-flag report.
- **Ops.** The ruleset version and how it is kept fresh, the event transport, every sink's lag and last error, and the in-process buffer.

The sidebar groups them: **Flags** (Flags, Segments, Layers), **Experiments** (Experiments, Metrics), **Governance** (Approvals, Activity) and **Config** (Environments, Hygiene, Ops). The environment picker sits in the top bar; it turns amber when you are not looking at the app's own environment. Light and dark themes are a click in the sidebar footer.

The console runs on the control-plane in a [central setup](/docs/central-server); tenants have none.

## Other consoles, search and sign-out

The console joins the app's Agora console registry. With other Agora consoles installed (durable, telescope, payments, …), the brand menu in the sidebar switches between them, showing only the ones the signed-in person may open. **⌘K** (or **Ctrl K**) searches every one of them; here it finds flags by key or description and segments by key.

The sidebar footer shows who is signed in and a sign-out button. Both work without configuration: the person comes from `ctx.auth.user` (`fullName`, `name` or `email`, and the first of `role` / `roles`), and sign-out is the one authkit announces. Set them yourself when your app differs:

```ts title="config/flags_dashboard.ts"
import { defineConfig } from '@adonis-agora/flags/dashboard'

export default defineConfig({
  // Who the footer shows. Return null for no user row.
  viewer: (ctx) => {
    const user = ctx.auth.user
    return user ? { label: user.fullName ?? user.email, email: user.email, role: user.role } : null
  },
  // A POST route (the form carries the CSRF token), { href: '/logout' } for a link, or false for none.
  signOut: '/logout',
})
```

## MCP tools

With `@adonis-agora/agent`'s `mcp_provider` registered, the console's tools join the app's developer MCP endpoint (`/mcp/agora`). Nothing to configure in this lib. Access is the console's `authorize`: whoever can open the console can use the tools, and nobody else sees them. To let an MCP client in with a token while people sign in as usual, combine both checks:

```ts title="config/flags_dashboard.ts"
import env from '#start/env'
import { anyAuthorize, authorizeByToken, defineConfig } from '@adonis-agora/flags/dashboard'

export default defineConfig({
  authorize: anyAuthorize(
    authorizeByToken({ token: env.get('CONSOLE_TOKEN') }),
    (ctx) => ctx.auth.user?.isAdmin ?? false,
  ),
})
```

Read tools are always listed: `flags_get_overview`, `flags_list_flags`, `flags_get_flag`, `flags_evaluate` (what a subject gets and why), `flags_list_segments`, `flags_list_metrics`, `flags_list_experiments`, `flags_get_experiment`, `flags_list_change_requests`, `flags_list_audit`, `flags_list_stale` and `flags_get_ops`.

The `flags_list_*` tools page like the other Agora libs' tools: pass `limit` (default 20, at most 100) and `page`, and each returns `{ items, next }`, where `next` is the page to ask for next, or `null` on the last one.

Action tools are listed only when the app allows actions on the dev endpoint (`devTools.actions` in `config/mcp.ts`): `flags_set_enabled`, `flags_set_rollout`, `flags_set_variant`, `flags_set_override`, `flags_save_flag`, `flags_save_segment`, `flags_save_metric`, `flags_recompute_experiment`, `flags_approve_change_request` and `flags_reject_change_request`.

Actions go through the same validation, approvals and history as the console. Where an environment needs approval, a change becomes a change request. The history records the signed-in person, or `mcp:token:<fingerprint>` for a token.

## The console API

Everything the console does goes through JSON endpoints under `<path>/api`, behind the same `authorize`. Writes carry the `x-xsrf-token` header when `@adonisjs/shield` sets the `XSRF-TOKEN` cookie. Every endpoint takes `?environment=` (or `environment` in the body).

| Request | Body | Does |
|---|---|---|
| `GET /api/flags` | | `{ data }`: flags, declarations and what each serves |
| `POST /api/flags` | `{ key, declaration }` | Create a flag |
| `PUT /api/flags/:key` | `{ definition, note? }` | Replace a flag's targeting |
| `POST /api/flags/:key/enabled` | `{ enabled }` | The kill switch: `false` serves `offVariant` to everyone; `true` lifts it, back to the targeting |
| `POST /api/flags/:key/rollout` | `{ percent }` | Percentage rollout of an on/off flag |
| `POST /api/flags/:key/variant` | `{ variant }` | Serve one variant to everyone |
| `GET /api/metrics` | | `{ data }`: config and console metrics, and the experiments using each |
| `PUT /api/metrics/:key` | `{ metric, note? }` | Create or replace a console metric (`409` for one defined in config) |
| `DELETE /api/metrics/:key` | | Delete a console metric (`422` while an experiment uses it) |
| `GET /api/audit` | | The change history, newest first (paged, see below) |
| `GET /api/change-requests` | | Change requests, newest first (paged) |
| `GET /api/schedules` | | Scheduled changes, soonest first (paged) |
| `GET /api/consoles` | | The other Agora consoles the signed-in person may open |
| `GET /api/consoles/search?q=` | | Search across those consoles and this one |

The catalogs (`/api/flags`, `/api/segments`, `/api/layers`, `/api/metrics`, `/api/experiments`, `/api/stale`) return the whole environment as `{ data, … }`.

The history, change requests and schedules speak the [filter](/docs/filter) list format: `filter[field]=value` to narrow, `first` for the page size, and `{ data, meta: { nextCursor, prevCursor, hasNext, hasPrev } }` back. An unknown filter field, a value it does not accept, or a `sort` other than the list's own order answers `400`.

| List | Filters | Order | `first` |
|---|---|---|---|
| `GET /api/audit` | `entity` (`flag`, `segment`, `layer`, `metric`, `holdout`, `ruleset`), `key` | `-at` | default 50, at most 200 |
| `GET /api/change-requests` | `status` (`pending`, `approved`, `rejected`, `applied`, `cancelled`); none: every status | `-requestedAt` | default 100, at most 500 |
| `GET /api/schedules` | `flag`, `status` (`pending`, `running`, `done`, `failed`, `cancelled`) | `runAt` | default 100, at most 500 |

The history pages forward: send `meta.nextCursor` back as `after` for older changes.

```ts title="app/services/flag_history.ts"
import { filterQuery, type CursorPageResponse } from '@adonis-agora/filter-client'

const query = filterQuery().where('entity', 'flag').where('key', 'new_checkout').first(50)
const page: CursorPageResponse<AuditEntry> = await fetch(
  `/flags/api/audit?${query.toQueryString()}`,
).then((r) => r.json())

if (page.meta.nextCursor) query.after(page.meta.nextCursor) // the next, older page
```

Change requests and schedules answer one page: `meta.hasNext` says more match than `first`, so narrow the filter or raise `first`.

`enabled: true` does not turn a flag on: on a flag that was never configured, the targeting created for it still serves the default. Use `variant` (`on`) or a rollout.

A `definition`:

```json
{
  "variants": { "classic": "classic", "one_page": "one_page" },
  "enabled": true,
  "offVariant": "classic",
  "rules": [
    {
      "id": "pro",
      "conditions": [{ "attribute": "plan", "op": "in", "values": ["pro"] }],
      "serve": { "variant": "one_page" }
    }
  ],
  "fallthrough": { "split": [{ "variant": "classic", "weight": 1 }, { "variant": "one_page", "weight": 1 }] },
  "experiment": {}
}
```

`fallthrough` is `{ "variant": … }` or `{ "split": [...] }`; [Targeting](/docs/targeting) lists the operators, segments, overrides and prerequisites. A change that needs approval answers `202` with the pending request.
