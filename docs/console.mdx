`node ace configure @adonis-agora/flags` registers the console and publishes `config/flags_dashboard.ts`. It is served at `/flags`.

Who may open it and who is acting come from the [identity provider](/docs/authentication) in `config/flags.ts`. You can also set them here, which wins:

```ts title="config/flags_dashboard.ts"
import { defineConfig } from '@adonis-agora/flags/dashboard'

export default defineConfig({
  path: '/flags',
  authorize: async (ctx) => {
    if (!(await ctx.auth.check())) return { redirectTo: '/login' }
    return ctx.bouncer.allows(manageFlags)
  },
  // Who made a change, for the audit log and approvals.
  actor: (ctx) => (ctx.auth.user ? { id: String(ctx.auth.user.id), name: ctx.auth.user.email } : undefined),
})
```

With authkit, `identity: identities.authkit()` in `config/flags.ts` covers both.

<Callout type="warn">
  Without `authorize`, the console is open outside production and answers 403 in production. With approvals on, set `actor` (or sign people in): two anonymous people are the same actor, and nobody can approve their own change.
</Callout>

## What it has

- **Flags.** Create flags with **New flag** (type, default, variants, owner, expiry, browser exposure). Search by tag, owner or staleness. Each flag shows its declared type, default and owner, and what it serves. The kill switch is one click from the list. In the editor: variants, the fallthrough (fixed or split), ordered rules, overrides, prerequisites and experiment settings (layer, holdout, metrics, guardrails, control, confidence). A context tester shows what any subject would get and why. Below that, the flag's history and its scheduled changes, including gradual rollouts.
- **Segments, layers and the global holdout.**
- **Metrics.** Create, edit and delete the metrics experiments use, and see which experiments use each one. Metrics from `config/flags.ts` are listed read-only.
- **Experiments.** Exposures, the sample-ratio check, and per metric the lift, interval, p-value, sequential p-value and verdict. Guardrail alerts, and a button to recompute now.
- **Approvals.** Approve, reject or cancel pending change requests.
- **Environments.** Switch environments, export and import JSON, promote from one environment to another.
- **Hygiene.** The stale-flag report.
- **Ops.** The ruleset version and how it is kept fresh, the event transport, every sink's lag and last error, and the in-process buffer.

The console runs on the control-plane in a [central setup](/docs/central-server); tenants have none.

## The console API

Everything the console does goes through JSON endpoints under `<path>/api`, behind the same `authorize`. Writes carry the `x-xsrf-token` header when `@adonisjs/shield` sets the `XSRF-TOKEN` cookie. Every endpoint takes `?environment=` (or `environment` in the body).

| Request | Body | Does |
|---|---|---|
| `GET /api/flags` | | Flags, declarations and what each serves |
| `POST /api/flags` | `{ key, declaration }` | Create a flag |
| `PUT /api/flags/:key` | `{ definition, note? }` | Replace a flag's targeting |
| `POST /api/flags/:key/enabled` | `{ enabled }` | The kill switch: `false` serves `offVariant` to everyone; `true` lifts it, back to the targeting |
| `POST /api/flags/:key/rollout` | `{ percent }` | Percentage rollout of an on/off flag |
| `POST /api/flags/:key/variant` | `{ variant }` | Serve one variant to everyone |
| `GET /api/metrics` | | Config and console metrics, and the experiments using each |
| `PUT /api/metrics/:key` | `{ metric, note? }` | Create or replace a console metric (`409` for one defined in config) |
| `DELETE /api/metrics/:key` | | Delete a console metric (`422` while an experiment uses it) |
| `GET /api/audit?key=` | | The change history |

`enabled: true` does not turn a flag on: on a flag that was never configured, the targeting created for it still serves the default. Use `variant` (`on`) or a rollout.

A `definition`:

```json
{
  "variants": { "classic": "classic", "one_page": "one_page" },
  "enabled": true,
  "offVariant": "classic",
  "rules": [
    {
      "id": "pro",
      "conditions": [{ "attribute": "plan", "op": "in", "values": ["pro"] }],
      "serve": { "variant": "one_page" }
    }
  ],
  "fallthrough": { "split": [{ "variant": "classic", "weight": 1 }, { "variant": "one_page", "weight": 1 }] },
  "experiment": {}
}
```

`fallthrough` is `{ "variant": … }` or `{ "split": [...] }`; [Targeting](/docs/targeting) lists the operators, segments, overrides and prerequisites. A change that needs approval answers `202` with the pending request.
